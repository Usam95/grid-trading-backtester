Lesson 0006 · Infrastructure · 4 minutes

ZRS keeps several zone copies of one stored object.

It helps when an Azure availability zone fails. It does not run a second trading system, validate your data, or undo every deletion.

The acronym

Zone-redundant storage

Azure synchronously stores a Blob object across three or more availability zones inside one Azure region.

Zone A

A copy of the verified recovery object exists here.

Zone B

Azure maintains another synchronized copy here.

Zone C

A zone outage can leave other copies available.

The copies are one Azure Blob object from your perspective. The application does not select or reconcile three files.

Concrete failure

Your VM's zone becomes unavailable.

The VM and its LRS disk may be unavailable, while the previously verified ZRS recovery point remains available from another zone.

1
Before failure
The runtime publishes a verified SQLite recovery point and manifest to ZRS Blob.
2
Zone fails
The single trading VM stops. ZRS does not keep it running.
3
Frozen rebuild
Infrastructure is recreated and restores a verified ZRS object, then replays, checks invariants, and reconciles Binance.
4
Operator review
Recovery ends frozen. It never resumes trading automatically.

Boundary

Replication repeats both good and bad changes.

If an authorized operation deletes an object, Azure can replicate that deletion too. Separate controls are still required.
