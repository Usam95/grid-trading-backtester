Chapter 1

Capital has an owner and a job.

A grid cannot safely use “whatever is in the account.” It owns an explicit allocation and must explain every base and quote unit.

Pair

Base and quote

In BTC/USDT, BTC is the base asset being traded. USDT is the quote asset used to price and pay for BTC.

Ownership

Grid inventory

BTC explicitly owned by this grid. Other BTC in the Binance account is merely a base holding and cannot be silently claimed.

Isolation

Grid allocation

Reserved BTC and USDT that manual trading or another algorithm must not consume while this run is open.

Neutral spot bootstrap

“Neutral” does not mean zero price exposure. It means the grid can place buys below and sells above immediately. To back those sells, it performs a real, journaled bootstrap acquisition.

required bootstrap base = Σ(initial sell-rung quantities) + fee/rounding shortfall

The market purchase pays real fees and slippage. No synthetic balance conversion is allowed in live mode.

Fixed quote sizing

Every rung commits approximately the same quote value. A 100 USDT rung buys more BTC at 80 than at 120.

base quantity ≈ fixed quote value ÷ rung price

When a buy fills, its sell uses the actual net base received. Profit stays as uncommitted quote; the MVP does not compound it automatically.

Chapter 2

The approved ladder is a boundary, not a suggestion.

Explore how bounds, rung count, spacing, and activation price determine initial orders and required backing inventory.

Rejected: activation price must be strictly inside both bounds. No bootstrap and no orders occur.

Rung count

Counts actual prices, including both bounds. Five rungs from 80 to 120 arithmetic means 80, 90, 100, 110, 120.

Geometric default

Equal percentage steps. Arithmetic remains supported but uses equal absolute price steps.

Activation rung

If market price exactly equals a rung, that rung begins inactive. Orders start strictly above and below it.

Chapter 3

Fills—not wishes—move inventory.

Every venue-confirmed fill changes ownership immediately. The paired order follows the actual executed quantity.

A partial-fill cycle

1
Intent
A post-only buy requests 0.010 BTC at rung 90.
2
Partial fill
Only 0.004 BTC executes. Ownership and accounting change now—not after the order completes.
3
Net inventory
If the fee is charged in BTC, the paired amount is net base received, not gross filled quantity.
4
Cumulative pair
One sell at the next rung is created or updated. Below-minimum quantity remains pending until tradeable.
5
Cycle closes
After the sell fills, the replacement buy returns one rung lower using the original fixed quote commitment.

Rules that prevent drift

  • One managed order per rung; never buy and sell simultaneously at one price.
  • Lowest rung stays buy-only; highest stays sell-only.
  • Interior rungs may change side through fill pairing.
  • No fill is synthesized because price merely touched a level.
  • Actual fee asset and fee quantity are recorded.
  • Each adjacent cycle must remain positive after conservative costs.
Post-only: normal rungs should rest as maker orders. Bootstrap and stop-loss liquidation are aggressive because completion matters more than maker status.

Chapter 4

“Not trading” has several meanings.

Select a scenario. Notice which states may resume and which permanently end a run.

Bootstrapping→ Active↔ Range-exhausted↔ Paused→ Closed Emergency

Active inside range

Buy rungs rest below price and backed sell rungs rest above it. Fills pair inward by one rung.

Pause

Cancel and block buys, keep valid inventory-reducing sells. Resume only after reconciliation and explicit approval.

Operator stop

Cancel all orders, reconcile late fills, then deliberately retain or liquidate. The run cannot resume.

Emergency stop

Block commands, cancel all managed orders, reconcile, and retain inventory. Do not auto-liquidate during uncertain state.

Late-fill reconciliation

You cancel a 0.010 BTC sell. While cancellation is being processed, 0.004 BTC executes. Final truth is 0.004 sold and 0.006 canceled—not 0.010 retained. Reconciliation applies that fill, fee, quote proceeds, and inventory reduction before deciding what remains.

Chapter 5

Safety preserves truth before it preserves activity.

The MVP favors explainable state and bounded exposure over uninterrupted trading.

Immutable configuration

Bounds, rungs, sizing, spacing, bootstrap, and stop-loss belong to one configuration version. Editing them creates a new version, new evidence, and a new run.

Risk limits may tighten during a run, but loosening them requires new approval.

Existing-account isolation

Your existing Binance account is allowed, but allocated BTC/USDT and the active symbol are exclusive to this grid. Unknown activity triggers a safety pause and reconciliation.

Concurrent algorithms later need subaccount isolation or a portfolio allocator.

Positive net cycle

Every adjacent cycle must remain profitable after maker fees, conservative execution allowance, venue rounding, and safety margin. Otherwise activation is rejected.

Global stop-loss

Paired sells take normal rung profit. A configured global stop-loss cancels, reconciles, liquidates remaining grid inventory, and permanently closes the run.

A stop trigger is not a guaranteed execution price; gaps can create additional slippage.

Open-ended lifecycle

A run has no preset expiry. It continues cycling until an explicit terminal event such as operator stop, emergency closure procedure, or global stop-loss permanently ends it.

Outer-rung cycling

The lowest rung remains buy-only and the highest remains sell-only. Fills may cycle back toward the ladder, but the system never adds a rung or creates exposure beyond the configured bounds.

Official Binance documentation warns that a timeout or server error can leave execution status unknown. Production code must query or stream authoritative order status rather than treating every error as a failed order. See Binance Spot REST API.
