- 2026-07-17: Operator selected one durable ingress sequencer inside each mode-isolated runtime. Concurrent adapters cannot mutate domain state; all decision-relevant inputs are validated, deduplicated, durably admitted, assigned one processing sequence, and processed by a single writer with atomic journal/outbox/accounting consequences. Silent dropping or overwriting is prohibited; lost admission capacity or continuity freezes only the affected runtime. Exact cross-source ordering and bounded backpressure thresholds remain to resolve.
- 2026-07-17: Operator selected corrected observed-order semantics after an earlier-contract conflict was surfaced. Online facts preserve causation, source order, and actual durable admission order; late facts are appended and reconciled, never inserted retroactively. Deterministic priority is only the fallback where no real order exists, using the existing execution/account-first table. Authenticated stop/pause requests activate a fail-closed runtime dispatch interlock that blocks unsent placement/replacement without reordering history or acknowledging before durable admission. Bounded staging and overload behavior remain next.
- 2026-07-17: Operator selected deadline-based backpressure with benchmark-sized bounded staging. Small in-memory source buffers feed each runtime's durable inbox; item/byte/age limits come from the mandatory 24-hour B1ms benchmark and fault suite. Reserved safety/evidence capacity and low-priority-work shedding precede source-specific freeze/degradation deadlines. Decision evidence is never dropped or coalesced, public-stream overflow becomes an explicit gap, and B1ms failure requires resize/retest rather than weaker isolation or a broker. Ingress/concurrency/backpressure is resolved; lifecycle is next.

Every replacement process starts frozen, rebuilds and verifies state, reconciles/cancels surviving managed orders where applicable, and waits at frozen readiness for explicit mode-specific authority. Operating never implies order permission; shutdown retains the accepted 60-second clean/incomplete proof. Lifecycle is resolved; durable command dispatch and unknown outcomes are next.

## Answer

Use the operator-approved [`analysis/online-runtime-and-recovery-spec.md`](../../../analysis/online-runtime-and-recovery-spec.md) as the MVP online-runtime contract. It specifies the laptop/Azure boundary; three-process qualification topology; per-runtime durable ingress and single-writer processing; observed-order semantics and the safety-command interlock; lifecycle and frozen recovery; command ambiguity, streams, reconciliation, mode adapters, operator commands, shutdown/restart, B1ms background scheduling, degraded dependency behavior, and the complete implementation/acceptance handoff.

The resolution deliberately keeps deployment to a modular single-node design while preserving explicit ports for future venues and modes. It does not assert that the current code implements these contracts or authorize paper, Testnet, or live trading.
