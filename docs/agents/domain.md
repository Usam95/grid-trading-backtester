# Domain Docs

Before exploring, read the root `CONTEXT-MAP.md`, every linked context relevant to the task, and applicable system or context ADRs. Missing files are created lazily through domain modeling.

Use glossary terms consistently. If code or discussion conflicts with a glossary definition, surface the conflict. If work contradicts an ADR, identify the ADR rather than silently overriding it.

This is a multi-context workspace: system-wide decisions live in `docs/adr/`; context vocabulary and decisions live at the paths listed in `CONTEXT-MAP.md`.
